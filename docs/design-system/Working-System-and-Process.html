01 · The website

One product: the bilingual marketing site

The codebase is a single product — the public marketing website for the firm, built in Next.js 16 / React 19 / Tailwind v4 with react-icons. Every user-facing string exists as an { en, ko } pair; a one-click header toggle swaps the body font from Roboto to Noto Sans KR.

The six service lines are the spine

Every page navigates back to these six. They are the backbone of the information architecture, and the brand deliberately maps all six to the same olive — it never fragments by service.

02 · Page grammar

Pages are composed, not authored

A page is not a blank canvas — it is a composition of named section patterns. A service page is built only from the catalog below, in a fixed order, with four to six body sections.

HeaderShared · never edited
01Hero · split with motion objectrequired · first
02 / 03Explainerchoose one
03 / 04 / 05Detail — image&text · lifecycle · calendarchoose one
06Quote / principle momentoptional
07Related servicesrequired
08Universal closing — insights · contact · footerrequired · last · byte-identical

The explainer is a variant family, not one shape

Pattern 02 is deliberately not a single layout. Each service picks the variant that fits its actual content — parallel domains get a list; related domains get a diagram. This is the texture that keeps six pages from becoming monotonous.

VariantShapeUsed byChosen because
ATwo-column text listtaxSub-areas are parallel domains — no hierarchy or sequence
BDiagram-led + 3-col detailsaccountingSub-areas have a visual relationship — a diagram earns its place
CNumbered methodology timelineconsulting · assuranceWork is a sequence of phases / procedures
DImage-led card grid + FAQhrOpen-clause imagery fits; FAQ answers real questions
ELifecycle 3-stage + calloutcorporateThe service maps to a business lifecycle (start-up → exit)
The rule that governs the whole grammar
If a page needs a section type that is not in the catalog, it does not become a page first and a playbook entry later. It becomes a playbook entry first, gets reviewed, then becomes a page.

Ranges, not fixed values

Several patterns define a permitted range rather than a single fixed value — the explainer motif, the image corner radius, the lifecycle stage count, the values count. A fixed value makes every page identical; an unbounded value lets drift back in. A bounded range is the resolution — generative enough to feel designed, constrained enough that it can't leave the brand.

04 · How consistency is maintained in Claude

A governance loop, not a single prompt

Consistency does not come from asking Claude nicely. It comes from a closed loop where every page is specified before it is built, linted as it is built, and audited after — and where the rules and patterns are written down, append-only, so context never has to be reconstructed from memory.

→ READ

1 · Decisions & rules

Start by reading the three most recent decisions and the foundational direction. They hold in-flight context that may not be reflected elsewhere yet.

decisions/ · SKILL.md
→ SPEC

2 · Playbook & brief

Pick the section patterns from the grammar. If a brief exists for the page, it is the spec — follow it section by section.

playbooks/ · briefs/
→ BUILD

3 · Generate

Build the page from real bilingual copy and brand tokens. Choose the explainer variant from the content, not by default.

colors_and_type.css · ui_kits/
→ LINT

4 · Run the gate

Grep the new page against the forbidden patterns and the hex allowlist. Blockers must return nothing.

rules/forbidden.json
→ AUDIT

5 · Score it

Produce an HTML audit showing how the page lands against the system — heroes, architecture, tokens, voice, findings.

audits/
↺ REVIEW

6 · Taste gate

The founder reviews the audit in five minutes, approves or redirects. A redirect becomes a new append-only decision — and the loop closes.

decisions/ (next)

The loop is what makes the work resumable: a new session reads the same decisions, playbooks and rules and arrives at the same place — no drift between sessions, because nothing lives only in a conversation.

Why append-only matters
Decisions are never edited — a superseding decision links forward instead. This means the reasoning survives, not just the outcome. "Drift starts when the 'why' gets lost," so every rule carries its rationale and every decision carries what was rejected and why.

05 · Source of truth

The system wins on brand; the codebase wins on copy

When the design system and the live codebase are mounted together, they each own different questions — and one critical rule prevents the most common mistake.

The system is truth for…

  • Colour, type, spacing, motion
  • Hover & press behaviour
  • The section grammar
  • Voice & tone
  • The no-shadow / no-blur / single-hue discipline

The codebase is truth for…

  • Real bilingual strings (pageUtils.ts)
  • Page structure & routes
  • Service → accent mapping
  • Icon exports (icons.ts)
  • Anything factual about content
The rule that prevents drift
The codebase has drifted from the system — it contains shadows, blurs and other patterns the system prohibits. When the two disagree on anything visual, the system wins. Never infer a brand pattern from the codebase — read it from the system. Copy is pulled, never reinvented; brand is read, never inferred.

06 · The lint

The discipline, encoded

Every "no X" rule lives in rules/forbidden.json — 17 rules, each with a regex or AST check, a target glob, a severity, and a rationale. A lint hook walks them against any new page. These are a representative subset.

blocker remove urgently drift fix when touching the page voice copy violates the documented tone
RuleSeverityWhy
No box / text shadowblockerDepth is colour-swap and the NE corner, never shadow. The most common path back into generic SaaS.
No backdrop-filter / blurblockerNo frosted glass. Opacity tiers (30/50/70/80), never a blur.
No mix-blend-modeblockerHover is colour-swap, not blend-mode darkening — the exact failure Direction B fixed.
No multi-hue gradientblockerThe only permitted gradient is the single-hue radial hero vignette.
No non-token hexdriftOne olive hue plus ink/cream/charcoal. Kills the historical purple & yellow timeline colours.
No unicode glyph iconsdriftArrows, checks, bullets are react-icons SVGs — never → ✓ • as text.
No placeholder text shippedblockerLorem ipsum under the Tax timeline (F01) was the one unacceptable outcome.
No radius outside vocabularydriftOnly 0 · 30px · 300px · pill. Arbitrary rounded-lg dilutes the signature gesture.
No invented contentvoiceNo fictional client names or [ 00 ] editorial labels — a voice violation.
Bilingual strings paireddriftEvery rendered string needs both en and ko. Drift starts with an English-only string.

The gate, in practice

# forbidden patterns in the new page — must return nothing
grep -nE "box-shadow|text-shadow|backdrop-filter|mix-blend-mode|linear-gradient\(|shadow-(sm|md|lg|xl|2xl)" \
  app/<service>-service/page.tsx

# off-token hex — anything outside the olive + ink + cream allowlist is a finding
grep -nEo '#[0-9A-Fa-f]{6}' app/<service>-service/page.tsx | grep -vE "$ALLOW"

# unicode glyphs used as icons
grep -nE '>[^<]*[→✓●•★][^<]*<' app/<service>-service/page.tsx

07 · The drift story

Direction B — how the gate earned its place

The clearest proof of why the loop exists: while iterating, a parallel example homepage was built to "demonstrate the system." During audit it was found to violate the system's own README — predictable drift from generating without a strict gate. "Looks cool" beat "matches the system."

What the example drifted into

  • text-shadow on the hero headline
  • backdrop-filter: blur(8px) sticky header
  • mix-blend-mode + gradient scrims on a video hero
  • SVG noise-grain texture overlay
  • Italic as a recurring emphasis device
  • Editorial-agency tone — [ 00 ] labels, invented client names, ticker copy

What Direction B chose

  • Bring the page back to the system — same copy & ambition, violating treatments removed
  • Photographic hero in place of video
  • Colour-swap hovers in place of blend filters
  • Partnership copy in place of agency tickers
  • No italic as a pattern
  • And: encode the rules, write the playbooks, run audits — so it can't recur

The alternative — updating the system to match the cool new direction — was rejected: an editorial-agency look suits a creative studio, not a Hong Kong accounting and advisory firm. The system's restraint matches the actual business; the example was visual ambition outrunning that match. That single decision is why rules/, playbooks/, audits/ and decisions/ exist at all.

The meta-lesson, kept on the record
"Make it the same so we don't drift" and "make each one its own thing so the family has texture" are both design imperatives. After Tax and Accounting the system had texture — so the instruction became: don't now systematise the texture itself into a new monotony. Each remaining page picks its variant from its actual content.
