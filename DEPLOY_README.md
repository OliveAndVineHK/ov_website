# Olive & Vine — Deployment Guide (for developers)

Marketing website for Olive & Vine. **Next.js 16 (App Router) · React 19 · Tailwind 4 · TypeScript 5 · MUI 7**.
This zip contains the source + assets only; `node_modules`, `.next`, `.git`, and `.env.local` are **excluded** (dependencies and build cache are regenerated by the commands below).

---

## 1. Requirements

- **Node.js 20 LTS** or newer (recommended: 20 or 22). The bundled `.nvmrc` pins `20`.
- npm (ships with Node). pnpm/yarn not required.
- OS-independent (Windows / macOS / Linux). No OS-specific commands in the `package.json` scripts.

---

## 2. Run locally

```bash
# 1) Unzip and enter the folder
cd olive-and-vine-clone-v3.0

# 2) Install dependencies (exact, from the lockfile)
npm ci          # or: npm install

# 3) Dev server
npm run dev     # http://localhost:3000

# 4) Verify a production build (recommended before deploying)
npm run build
npm start       # run the build locally in production mode
```

> **No secret keys are required** to build or run. `npm run dev` / `npm run build` work with no environment variables (the variables below all have fallbacks). However, **for production set `NEXT_PUBLIC_SITE_URL` to the real domain** — otherwise the sitemap, canonical URLs, and SEO metadata point to staging (`test.oliveandvinehk.com`).

---

## 3. Environment variables

Create a `.env.local` file at the project root (this file is not included in git/zip).

| Variable | When needed | Description |
| --- | --- | --- |
| `NEXT_PUBLIC_SITE_URL` | **Recommended for production** | Absolute site URL, e.g. `https://oliveandvinehk.com`. Falls back to the staging URL if unset. Used by sitemap, robots, structured data, and canonical tags. |
| `NEXT_PUBLIC_GOOGLE_SITE_VERIFICATION` | Optional | Google Search Console verification token. |
| `NEXT_PUBLIC_BING_SITE_VERIFICATION` | Optional | Bing verification token. |
| `DEEPL_API_KEY` | Optional (tooling only) | **Not needed by the site at runtime.** Used only by the translation scripts in `i18n/scripts/`. |
| `DEEPL_GLOSSARY_ID` | Optional (tooling only) | Same as above (DeepL glossary ID). |

Example `.env.local` (production):

```bash
NEXT_PUBLIC_SITE_URL=https://oliveandvinehk.com
# Optional:
# NEXT_PUBLIC_GOOGLE_SITE_VERIFICATION=xxxxxxxx
# NEXT_PUBLIC_BING_SITE_VERIFICATION=xxxxxxxx
# DEEPL_API_KEY=...        # only if running the translation scripts
# DEEPL_GLOSSARY_ID=...
```

> ⚠️ The DeepL key was exposed previously — **rotate it before use**. Never commit or share `.env.local`.

## 4. Deploy to Vercel

Two ways to ship to the existing Vercel project (the link currently in use):

**Option A — Git connection (recommended)**
1. Push this source to the company GitHub repo (`git init` → commit → `git remote add` → `git push`).
2. Connect the Vercel project to that repo (or, if already connected, a push triggers an automatic deploy).
3. In the Vercel dashboard → **Project → Settings → Environment Variables**, set the variables above (at minimum `NEXT_PUBLIC_SITE_URL`). Configure Production and Preview environments separately.
4. Each push builds and deploys automatically.

**Option B — Vercel CLI**
```bash
npm i -g vercel
vercel            # preview deploy
vercel --prod     # production deploy
```

> Vercel builds run on Linux. This code has already been deployed to Vercel before, so Linux build issues such as case-sensitive imports are already resolved.

## 5. Windows notes

- `npm ci` → `npm run dev` works as-is (no OS-specific scripts).
- Automatic CRLF line-ending conversion does not break the build. If linters complain, add `* text=auto eol=lf` to a `.gitattributes` file.
- Rarely, deep `node_modules` paths may exceed the Windows path limit: run `git config --system core.longpaths true`, or enable Windows long paths.

## 6. Asset optimization included in this version

The heavy first-paint assets that made the deployed site feel slower than local have been reduced:

| Asset | Before | After |
| --- | --- | --- |
| `public/home/home-bg-movie.mp4` (hero video) | 28MB | **2.8MB** (re-encoded H.264, no audio, faststart) |
| `public/home/regional-operations.svg` | 29.6MB | **0.70MB** |
| `public/home/mission-driven.svg` | 24.8MB | **0.23MB** |
| `public/home/business-growth.svg` | 17.6MB | **1.02MB** |
| `public/home/new-ventures.svg` | 5.4MB | **0.16MB** |
| `public/services/b1.svg` | 9.1MB | **0.31MB** |
| `public/services/a1.svg` | 4.3MB | **0.29MB** |
| **`public/` total** | **152MB** | **~40MB** |

- Those SVGs were "an SVG with a 4K raster (PNG/JPEG) embedded inside"; the embedded image was downscaled to 1920px and recompressed as JPEG. **Same filenames/paths → no code changes.**
- Insight card images (`public/insights/*.jpg`) are rendered via `next/image`, which **resizes and serves WebP automatically** on delivery, so they need no manual optimization.
- `public/home/home-bg.png` was intentionally left untouched — it is the hero notch **alpha mask + video poster** (changing it would break the notch).

### Remaining optimizations (optional, later)
- `home-bg.png` (2.4MB): can be shrunk with `pngquant` while preserving alpha (verify mask precision afterward).
- MUI is currently used only by the FAQ accordion — replacing it with a lightweight custom accordion would reduce the JS bundle.
- After deploying, run **Lighthouse / Web Vitals** to check LCP and CLS further.
- The unused `/subscribe` page and assets are intentionally retained (only the links were removed).
